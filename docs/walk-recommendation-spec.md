# Meoksa 산책 코스 추천 설계서

작성일 2026-08-08. 본 문서를 추천 로직의 단일 기준으로 함.

## 1. 개요

사용자 현재 위치에서 출발하여 동일 지점으로 복귀하는 순환 코스 3개를 추천함.
반려견의 견종·나이·성격과 도로 안전·환경 데이터를 반영하며, 추천 근거를 함께 제시함.

## 2. 서비스 지역

2.1. 서울특별시 전역 (605 km²)

2.2. 용인시 처인구 일부

    명지대학교 자연캠퍼스(37.2210, 127.1865) 중심 반경 3km
    역북동 포함 (캠퍼스 기준 북쪽 1.6km)

2.3. 설계 원칙

    모든 기능은 전국 표준데이터만으로 동작해야 함.
    서울 전용 데이터(서울시 가로수 상세, 서울 실시간 도시데이터, TOPIS)는
    서울 권역의 정확도 보강 용도로만 사용함.
    특정 기능이 서울 전용 데이터에만 의존할 경우 용인 권역에서 동작하지 않음.

2.4. 도로 밀도 실측치 (OSM, 반경 300m 보행가능 도로)

| 항목 | 구의역 | 명지대 자연캠 |
|---|---|---|
| 도로 수 | 102 | 51 |
| 사용 가능 방위 (8방위 중) | 5 | 6 |
| 30분 코스 3개 생성 | 가능 | 가능 |

## 3. 반영 요소

요소별 처리 방식을 네 가지로 구분함. 구현 시 이 구분을 기준으로 모듈을 분리할 것.

    경고    코스 순위와 무관. 화면 상단 배너로 표시
    거리    점수가 아닌 목표 시간·거리 결정
    탐색    GraphHopper 커스텀 모델로 경로 생성 단계에 반영
    채점    생성된 후보를 PostGIS로 채점

### 3.1. 기본 원칙 (전체 공통)

| 요소 | 처리 | 구현 방법 |
|---|---|---|
| 인도 위주 | 탐색 | road_class FOOTWAY/PEDESTRIAN → priority 1.5 |
| 보차 분리 | 탐색 | PRIMARY 0.15 / SECONDARY 0.3 / RESIDENTIAL 0.8 / LIVING_STREET 1.3 |
| 가로수 밀도 | 채점 | ST_DWithin(path, tree, 20) 개수 ÷ km |
| 횡단보도 최소화 | 채점 | TMAP facilityType 15 개수 (선택 항목) |

차량 노출도는 도로 등급이 아닌 보차 분리 여부를 기준으로 해석함.
주택가 골목은 인도가 없어 차량과 노면을 공유하고 불법주차로 시야가 차단되므로
대로변보다 위험도가 높을 수 있음. PRD 문제 정의에서도 골목을 지목함.

### 3.2. 견종 기반

| 요소 | 처리 | 구현 방법 |
|---|---|---|
| 활발함 및 견종 특성 | 거리 | KC 4단계 등급 × 체급 × 나이 |
| 고관절 주의 (대형견) | 탐색 | average_slope > 6 → priority 0.3 |
| 단두종 여름 위험 | 경고 | 더위 기준 3℃ 하향. 점수 미반영 |
| 단두종 활동량 저하 | 거리 | 목표 시간 × 0.7 |

단두종 목록: 퍼그, 불독, 프렌치불독, 시츄, 페키니즈, 보스턴테리어, 복서

슬개골(푸들·포메) 및 허리(닥스훈트·코기)에는 계단 필터를 적용하지 않음.
예방 근거가 확인되지 않았으며 닥스훈트는 반대 결과가 존재함(9절 참고).
계단 필터는 노령견, 질환 기재 개체, 3개월 이하 대형견 퍼피에만 적용함.

### 3.3. 나이 기반

| 요소 | 처리 | 구현 방법 |
|---|---|---|
| 퍼피 (12개월 미만) | 거리 | × 0.6 |
| 퍼피 3개월 이하 (대형견) | 탐색 | STEPS → priority 0 |
| 노령견 산책량 감소 | 거리 | × 0.6 (초고령 0.45) |
| 노령견 계단 회피 | 탐색 | STEPS → priority 0 |
| 노령견 경사 회피 | 탐색 | average_slope > 4 → priority 0.2 |
| 노령견 벤치 필요 | 채점 | OSM amenity=bench 근접 개수 |

노령 기준

    대형견 7세 이상
    중형견 8세 이상
    소형견 10세 이상
    초고령 = 노령 기준 + 4세

### 3.4. 성격 설문 기반

| 설문 응답 | 처리 | 구현 방법 |
|---|---|---|
| 모험 선호 | 채점 | seed 매회 변경, 최근 이용 코스 감점 |
| 겁 많음 | 채점 | seed 고정, 익숙한 경로 반복 |
| 자동차 무서워함 | 탐색 | PRIMARY 0.05, SECONDARY 0.1 |
| 사람 무서워함 | 채점 | 혼잡도 감점 |
| 개 만나기 선호 | 탐색·채점 | 야외 반려견 놀이터·공원 경유 가산 |
| 개 회피 | 채점 | 개 마주칠 확률 감점 |
| 공원 선호 | 탐색 | in_park → priority 2.0 |

### 3.5. 환경 기반 (실시간)

| 요소 | 처리 | 구현 방법 |
|---|---|---|
| 미세먼지·악천후 | 경고·거리 | 배너 표시 및 목표 시간 단축 |
| 여름 주간 | 경고 | 코스 변경이 아닌 시간 변경 권유 |
| 야간 | 탐색 | lit == true → priority 1.3 |
| 겨울 제설제 | 경고 | 강설 후 3일간 안내 |

### 3.6. 편의 시설

| 요소 | 처리 | 구현 방법 |
|---|---|---|
| 벤치·쉼터 | 채점 | 노령견에 한해 가산 |

### 3.7. 제외 항목

다음 항목은 검토 후 제외함. 재도입 시 별도 협의 필요.

    1. 맹견 5종 입마개 및 혼잡 회피
    2. 출퇴근·하교 시간대 처리
    3. 배변봉투함, 음수대, 동물병원 근접도
    4. 노면 종류 (OSM surface 커버리지 17%로 실효성 없음)
    5. 그늘 계산 (MVP 범위 제외)

### 5.1. 경고 체크

3단계로 구분함: 정상, 주의, 위험

| 항목 | 주의 | 위험 |
|---|---|---|
| PM10 | 81 ~ 150 | 151 이상 |
| PM2.5 | 36 ~ 75 | 76 이상 |
| 체감온도 (더위) | 28 ~ 30℃ | 31℃ 이상 |
| 체감온도 (추위) | -5 ~ 0℃ | -6℃ 이하 |
| 강수 | 비, 눈 | 호우·대설 특보 |

견종·나이별 기준 조정

| 대상 | 조정값 |
|---|---|
| 단두종 | 더위 기준 -3℃ |
| 이중모 (허스키, 사모예드, 포메라니안) | 더위 기준 -2℃ |
| 소형견 5kg 미만 | 추위 기준 +3℃ |
| 퍼피, 노령견 | 더위 -2℃, 추위 +2℃ |

여름 주간 처리

    조건: 체감온도 28℃ 이상 그리고 시각 12시 ~ 17시
    출력: 코스 변경이 아닌 시간 변경 권유

아스팔트 표면 온도는 기온보다 20~25℃ 높음. 기온 30℃일 때 노면은 50℃대.

### 5.2. 목표 시간 계산

계산식

    1회 기본값 (체급별)
        Toy, Small  25분
        Medium      30분
        Large       30분
        Giant       25분

    × 견종 계수 (Royal Kennel Club 4단계 등급)
        Up to 30 minutes    0.7
        Up to 1 hour        1.0
        Up to 2 hours       1.3
        More than 2 hours   1.6

    × 나이 계수
        퍼피 (12개월 미만)  0.6
        1 ~ 3세             1.3
        4 ~ 7세             1.0
        노령                0.6
        초고령              0.45

    × 단두종 계수 0.7 (해당 시)
    × 활발함 계수 0.8 / 1.0 / 1.2 (설문 확정 후 적용)

    = 적정 시간

    최소 = max(10분, 적정 × 0.6)
    상한 = 적정 × 1.5 (퍼피, 노령견은 × 1.2)

시간-거리 변환 속도

| 체중 | 속도 |
|---|---|
| 5kg 미만 | 2.0 km/h |
| 5 ~ 10kg | 2.5 km/h |
| 10 ~ 25kg | 3.0 km/h |
| 25kg 이상 | 3.5 km/h |
| 노령견 | 위 값 × 0.8 |

체급 차이보다 나이 차이의 영향이 큼. 개 28,562마리 가속도계 실측 결과
체급 차이는 Toy 37.0분, Large 41.2분으로 4분에 그친 반면
나이 차이는 1.5세 68.6분, 10세 35.4분으로 33분이었음.

UI 표기는 시간을 주 단위로, 거리를 보조 단위로 함.

    최소       23분 (약 1.0km)
    적정       39분 (약 1.6km)  기본 선택
    직접 설정  23 ~ 59분 범위

### 5.3. 방위 선정

절차

    1. 집 좌표 기준 반경 300m 보행가능 도로 조회 (PostGIS)
    2. 각 도로 중심점의 방위각 계산 후 8방위로 분류
    3. 도로 수 상위 3개 방위 선택
    4. 도로 8개 미만 방위는 제외 (경로 생성 실패 방지)

방위각 기준

    0도 북, 45도 북동, 90도 동, 135도 남동
    180도 남, 225도 남서, 270도 서, 315도 북서

격자 200m 단위로 사전 계산하여 캐시함.

### 5.4. 코스 생성

GraphHopper round_trip 알고리즘과 커스텀 모델을 함께 사용함.

round_trip 내부 동작

    1. 시작점을 도로망에 스냅
    2. 경유지 수만큼 반복
        이전 지점에서 거리와 방위각으로 좌표 투사 후 도로망에 스냅
        스냅 실패 시 거리를 5% 축소하여 재시도
    3. 마지막에 시작점 재추가
    4. 경유지를 순서대로 연결. AvoidEdgesWeighting으로 기이용 도로에 페널티 부과

파라미터

    경유지 수 = min(20, 2 + 거리(m) / 50000). 1.6km 기준 2개
    initialHeading = 5.3에서 선정한 3개 방위 주입
    seed = 방위당 2개
    총 후보 6개 (3방위 × seed 2), 병렬 호출

가중치 공식

    edge_weight = 거리 ÷ (속도 × priority) + 거리 × distance_influence + 회전페널티

priority만 조절함. speed를 변경하면 예상 소요 시간이 왜곡되므로 사용하지 않음.

기본 커스텀 모델

```json
{
  "priority": [
    { "if": "road_class == STEPS",         "multiply_by": 0    },
    { "if": "road_class == MOTORWAY",      "multiply_by": 0    },
    { "if": "road_class == TRUNK",         "multiply_by": 0    },
    { "if": "road_class == PRIMARY",       "multiply_by": 0.15 },
    { "if": "road_class == SECONDARY",     "multiply_by": 0.3  },
    { "if": "road_class == TERTIARY",      "multiply_by": 0.5  },
    { "if": "road_class == RESIDENTIAL",   "multiply_by": 0.8  },
    { "if": "road_class == LIVING_STREET", "multiply_by": 1.3  },
    { "if": "road_class == FOOTWAY",       "multiply_by": 1.5  },
    { "if": "road_class == PEDESTRIAN",    "multiply_by": 1.5  }
  ],
  "distance_influence": 70
}
```

| 자동차 무서워함 | PRIMARY 0.05, SECONDARY 0.1 |
| 공원 선호 | in_park → 2.0 (areas 사용) |
| 노령견 | STEPS 0, average_slope > 4 → 0.2 |
| 대형견 | average_slope > 6 → 0.3 |
| 야간 | lit == true → 1.3 |
| 3개월 이하 대형견 퍼피 | STEPS 0 |

커스텀 모델 제약

    1. "ch.disable": true 설정 필수. round_trip도 동일 조건이므로 충돌 없음
    2. POST /route에서만 동작. GET 불가
    3. areas는 Polygon만 지원. MultiPolygon 불가. 좌표는 [경도, 위도] 순, 첫 점과 끝 점 일치 필요
    4. 베타 기능이므로 GraphHopper 버전 고정 권장
    5. 자체 계산 데이터(가로수 밀도, 표준노드링크 점수)는 직접 주입 불가. 5.5에서 처리

사용 가능한 내장 속성

    road_class, surface, average_slope, lit, lanes, max_speed, road_environment

### 5.5. 사후 채점

커스텀 모델에 반영하지 못한 요소를 계산함. 후보 6개를 배치 쿼리 1회로 처리할 것.

| 항목 | 쿼리 |
|---|---|
| 가로수 밀도 | count(*) / (ST_Length(path::geography) / 1000), ST_DWithin(path, tree, 20) |
| 공원 비율 | ST_Length(ST_Intersection(path, park)) / ST_Length(path) |
| 위험구간 통과 | ST_Intersects(path, risk_zones) |
| 벤치 개수 | ST_DWithin(path, bench, 15) |
| 개 마주칠 확률 | 읍면동 반려견 등록 밀도 × 반려동물 시설 근접 × 공원 근접 |
| 다양성 | 최근 7일 walk_records와 ST_Intersection 비율 |

### 5.6. 채점 공식

1차 구현: 계층 필터

가중치를 정의할 필요가 없어 우선 구현함.

    1. 거리가 목표 ±20% 범위 밖이면 탈락
    2. 계단 포함 시 탈락 (해당 견종에 한함)
    3. 차량 노출도 낮은 순 정렬
    4. 동점 시 가로수 밀도 높은 순
    5. 재차 동점 시 공원 비율 높은 순

2차 확장: 3축 가중치

    안전 = (차량노출_정규화 + 횡단보도_정규화) / 2
    쾌적 = (가로수_정규화 + 공원비율) / 2
    적합 = 1 - |실제거리 - 목표거리| / (목표거리 × 0.5)

    총점 = 안전 × W안전 + 쾌적 × W쾌적 + 적합 × W적합

| 대상 | W안전 | W쾌적 | W적합 |
|---|---|---|---|
| 기본 | 40 | 30 | 30 |
| 자동차 무서워함 | 60 | 20 | 20 |
| 공원 선호 | 40 | 45 | 15 |
| 겁 많음 | 55 | 25 | 20 |

단순 가중합 방식은 사용하지 않음. 실제 코스 3개로 검증한 결과
대로변 코스가 가로수 밀도가 높다는 이유로 골목 코스보다 상위에 배치되는 문제가 발생함.
안전 항목은 다른 항목으로 상쇄될 수 없어야 함.

### 5.7. 최종 선정

방위별 최고점 1개씩 선택함. 동일 방위 코스가 상위를 차지할 경우
사용자 관점에서 구분되지 않기 때문임.
명지대 권역과 같이 도로 밀도가 낮은 지역은 1~2개만 제시함.

응답에 점수 내역을 포함함. AI 설명 생성 시 실측값을 근거로 사용하기 위함.

## 7. 성능

### 7.1. 서버 처리 시간

| 단계 | 예상 시간 |
|---|---|
| 경고 체크 (캐시 히트) | 10ms |
| 목표 시간 계산 | 0ms |
| 방위 선정 (격자 캐시) | 0ms |
| round_trip 6개 병렬 | 100ms |
| PostGIS 배치 채점 | 50ms |
| 가중치 적용 및 정렬 | 1ms |
| 합계 | 약 150ms |

### 7.2. 사용자 체감 시간

서버 계산은 전체의 5% 수준임.

| 구간 | 시간 |
|---|---|
| GPS 위치 획득 | 1,000 ~ 5,000ms |
| 네트워크 왕복 (모바일) | 100 ~ 300ms |
| 날씨·미세먼지 API (캐시 미스) | 400 ~ 1,000ms |
| 서버 파이프라인 | 150ms |
| 지도 렌더링 | 200 ~ 500ms |

### 7.3. 최적화 항목

    1. 앱 진입 즉시 GPS 및 날씨를 백그라운드로 선요청.
       사용자가 강아지와 시간을 선택하는 동안 완료됨
    2. 강아지 선택 시점에 "적정" 옵션을 사전 계산
    3. 캐시 키는 격자좌표 + 강아지ID + 목표시간 + 시간대(오전/오후/저녁), TTL 6시간
    4. TMAP은 파이프라인에 포함하지 않음. 9회 호출 시 2~4.5초가 소요되어 전체의 80% 차지
    5. 배치 처리(1일 1회): 도로 구간 점수 계산(서울 약 16만 구간 추정), 격자별 방위 분포

목표 응답 시간: 사전 준비 상태에서 0.5 ~ 1초
