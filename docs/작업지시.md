# 작업 지시 프롬프트 모음

Codex/Claude에 그대로 복사해서 쓰는 작업 단위 프롬프트.
`AGENTS.md`가 공통 규칙을 담당하므로 여기엔 **작업별 완료 조건만** 적는다.

화면 명세는 이 저장소에 두지 않는다 (노션 관리). 이 문서는 그 명세를
작업 단위로 쪼갠 것이다.

## 쓰는 법

- **한 번에 하나만** 준다. 두 개를 붙여 주면 둘 다 절반이 된다.
- 프롬프트를 줄 때 **아래 "확정된 설계"와 "기술 결정" 두 섹션을 같이 붙여넣는다.**
  작업별 프롬프트에는 그 작업 고유의 조건만 적혀 있다.
- 먼저 `구현하지 말고 계획만 말해`로 한 번 끊는다. 방향이 틀렸으면 여기서 잡힌다.
- 조건을 하나라도 못 지켰으면 **완료가 아니다.** 부분 완료를 받아주지 않는다.

# 확정된 설계

## 화면 구조

- **탭 5개**: 메인 / 산책하기 / 기록 / 셰어링 / 마이페이지.
  **메인과 산책하기는 서로 다른 탭이다.**
  - 메인 = 오늘의 산책 판단 + 강아지 정보 카드 + 오늘 밥·약·산책 진행률
  - 산책하기 = 산책 시간 선택 → 코스 추천 → 산책 중 화면
- **산책 중에는 산책하기 탭이 산책 화면으로 바뀐다.** 탭 바는 유지되고, 다른 탭으로
  이동해도 산책은 계속된다.
- **강아지 미등록 상태에서는 모든 탭이 "강아지를 먼저 등록해주세요" + 등록 버튼만
  보여준다.** 탭 바 자체는 보인다.

## 산책

- **사용자 지정 산책 시간은 20분 ~ 4시간.** 10분은 없앤다.
  `MINIMUM_DURATION_FLOOR_MINUTES` 도 10 → 20 으로 올린다.
  근거: 보행 속도 2.0~3.5km/h 기준 10분은 333~583m인데, GraphHopper round_trip은
  500m 요청 시 +26% 빗나가고 1km 근처부터 정확해진다. 20분이면 소형견도 667m다.
  그보다 짧은 산책은 자유 산책이 담당한다 (코스를 안 만들므로 오차가 없다).
- **자유 산책**: 코스를 추천하지 않고 바로 산책을 시작한다.
- **산책 체크는 자동.** 앱에서 산책을 끝내거나 수동 기록을 입력하면 셰어링의
  산책 횟수가 자동으로 올라간다. **손으로 체크하는 UI는 만들지 않는다** —
  경로가 둘이면 숫자가 어긋난다. 자유 산책도 카운트에 포함된다.

## 케어

- **진행률 상한은 목표치.** 2회 설정에 3번 걸어도 `3/2`가 아니라 `2/2`로 멈춘다.
- **밥·약은 시간대로 나눈다.** 2회 → 아침/저녁, 3회 → 아침/점심/저녁.
  `care_routines.times_of_day` 가 이미 이 구조를 지원한다.
- **밥·약·산책 횟수는 온보딩에서 입력받는다.** 신규 사용자가 빈 화면을 보지
  않도록 강아지 등록 단계에서 함께 물어본다.
- **횟수를 바꾸면 다음 날부터 적용된다.** 오늘 이미 만들어진 기록은 건드리지 않는다.
- **하루 리셋은 한국 시간 자정.** 코드에 `todayKeyKst()` 가 이미 있다.
- **찔러보기는 셰어링 탭 안의 목록.** 푸시 알림은 MVP 제외 항목이다.
- **초대 코드 생성은 셰어링 탭에 둔다.** 입력은 회원가입 단계에 있다.

## 온보딩·계정

- **온보딩은 두 갈래.** 초대 코드를 입력하면 가족의 강아지에 합류하고
  강아지 등록·성격 설문·케어 횟수 입력을 건너뛴다.
- **반려견 추가·삭제는 만들지 않는다.** `POST /api/dogs` 와
  `POST /api/dogs/join` 은 501 스텁 그대로 둔다.
- **`staticMapUrl` 은 제거한다.** → 작업 13

# 기술 결정

에이전트가 스스로 정하면 매번 달라지는 것들을 미리 못 박는다.
**이 섹션도 프롬프트와 함께 붙여넣을 것.**

| # | 항목 | 결정 |
|---|---|---|
| 1 | 탭 구현 방식 | Next App Router 라우트로 나눈다. `/`(메인) `/walk` `/records` `/sharing` `/my`. 클라이언트 상태 전환이 아니라 실제 경로여야 새로고침해도 같은 탭이 열린다 |
| 2 | 파일 배치 | 탭별 `app/<경로>/page.tsx`, 공용 컴포넌트는 `app/components/` 아래. 한 파일이 400줄을 넘으면 쪼갠다 |
| 3 | 현재 위치 획득 | `app/meoksa-app.tsx` 에 이미 있는 geolocation 로직을 공용으로 빼서 재사용한다. 새로 짜지 않는다 |
| 4 | 사용자 지정 시간 입력 | 슬라이더 + 현재 값 숫자 표시. 10분 단위로 움직인다 (20 / 30 / 40 …) |
| 5 | 최소·적정 시간 표시 | `GET /api/walk-routes/duration-options` 가 이미 계산해서 준다. "최소 산책 (25분)" 처럼 분 수를 함께 보여준다 |
| 6 | 자유 산책 시작 | 코스 추천을 건너뛰고 `POST /api/walk-records/start` 를 바로 호출한다. 기록 저장 경로는 일반 산책과 동일하다 |
| 7 | 산책 중 경로 저장 | 새 엔드포인트 `PATCH /api/walk-records/:id/progress` 를 만든다. `finish` 를 재사용하지 않는다 (finish는 종료 처리를 하므로) |
| 8 | 코스 저장 방식 | `walk_records` 에 `recommended_course jsonb` 컬럼 하나를 추가한다. 별도 테이블을 만들지 않는다 |
| 9 | 아침/점심/저녁 라벨 | `times_of_day` 의 시각으로 판정한다. 11:00 이전 아침, 17:00 이전 점심, 그 이후 저녁. 2회 설정이면 아침/저녁 |
| 10 | 산책 자동 카운트 구현 위치 | 산책 종료(`finish`)와 수동 기록(`manual`) 컨트롤러에서, 그날의 미완료 `care_tasks`(task_type='walk') 중 하나를 완료 처리한다. 남은 게 없으면 아무것도 하지 않는다 (상한 유지) |
| 11 | 리뷰 건너뛰기 | 리뷰 화면에 "나중에" 버튼을 둔다. 누르면 기록은 저장되고 별점·메모만 비어 있다 |
| 12 | 데이터 갱신 시점 | 탭에 들어갈 때마다 다시 조회한다. 실시간 구독이나 폴링은 만들지 않는다 |

## 로딩·에러 공통 규칙

모든 화면에 적용한다. 작업별 프롬프트에 매번 적지 않는다.

- 조회 중에는 빈 화면이 아니라 로딩 표시를 보여준다.
- API 하나가 실패해도 **그 카드만** 오류 문구를 보여주고 나머지 화면은 동작한다.
- 목록이 비면 빈 화면이 아니라 안내 문구를 보여준다.
- 사용자에게 보이는 문구는 전부 한국어다. 에러 코드를 그대로 노출하지 않는다.

# 작업 1 — 메인 탭

```
[작업]

- 위치 획득 로직을 새로 짜지 마라 (기술 결정 3).

# 작업 2 — 산책하기 탭: 시간 선택 + 자유 산책

```
[작업]
산책하기 탭의 시간 선택지를 명세대로 바꾸고 자유 산책을 추가해라.
이 작업 하나만 한다.

[배경]
현재 선택지는 최소 / 적정 / 사용자 지정 세 가지다.
src/constants/walk-tuning.ts 의 MINIMUM_DURATION_FLOOR_MINUTES 가 10이다.
GraphHopper round_trip 은 짧은 거리에서 크게 빗나간다 (500m 요청 → +26%,
1km 요청 → +6%). 10분은 체중에 따라 333~583m라 오차 구간에 정확히 들어간다.

[완료 조건] 전부 만족해야 완료다
1. 산책하기 탭에 선택지가 네 개 보인다:
   최소 산책 / 적정 산책 / 사용자 지정 / 자유 산책
2. 최소·적정 옆에 실제 분 수가 함께 보인다 (기술 결정 5). 예: "최소 산책 (25분)"
3. 사용자 지정은 슬라이더로 20분 ~ 4시간, 10분 단위로 고른다 (기술 결정 4).
   20분 미만은 선택할 수 없다.
4. MINIMUM_DURATION_FLOOR_MINUTES 가 20으로 바뀌어, 노령 소형견이라도
   "최소 산책"이 20분 아래로 내려가지 않는다.

## 아직 프롬프트를 안 만든 것들

MVP에 있지만 위 16개에 안 들어간 것. 필요해지면 같은 형식으로 만든다.

- **이메일 인증 화면** — 현재 Supabase 기본 이메일 링크에 의존한다.
  시연에서 이 흐름을 보여줄 거라면 화면이 필요하다. 안 보여줄 거면 그대로 둔다.
- **위치 권한 거부 시 주소 직접 입력** — MVP 예외 처리 항목.
  지금은 "위치를 알 수 없어요" 까지만 한다.
- **시연용 위치 고정 옵션 / 데모 시드 데이터** — 시연 준비 항목.
  시연 날짜가 정해지면 만든다.
